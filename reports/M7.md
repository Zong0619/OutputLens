## Architecture Impact

**None.** All M7 artifacts are external consumers of the engine. Three
interfaces (CLI, API, Web) were built and validated against the same
AnalysisDocument contract. This confirms:

- **Engine First, Interface Second**: Interfaces are rendering/transport
  layers. No analytical logic in any interface.
- **AnalysisDocument as contract**: All three interfaces consume the same
  versioned JSON schema. No interface depends on internal Python objects.
- **Interface independence**: Each interface can be built, tested, and
  modified without knowledge of the others.

The `engine_runner.py` module was extracted as a shared entry point to
ensure consistent engine invocation across interfaces.

## Known Limitations

- Interfaces are reference implementations, not production services.
- No authentication, authorization, or rate limiting.
- Web demo has no persistent user state.
- CLI/API/web demo serve single-request analysis only (no batch, no streaming).

## Lessons Learned

1. **Shared engine runner reduces duplication**: Extracting
   `engine_runner.run_analysis()` during Phase 7.2 eliminated ~80 lines
   of duplicated orchestration code and ensures all interfaces invoke the
   engine identically.
2. **Automated boundary tests prevent analytical creep**: Source inspection
   tests (checking for forbidden function names in interface code) caught
   the boundary concern before it became a problem.
3. **Optional dependencies work**: Flask is an `[api]` extra. Core engine
   has zero web dependencies. Tests run correctly both with and without
   Flask installed.
