## Architecture Impact

**None.** All M6 artifacts are external to the engine. The evaluation
infrastructure consumes AnalysisDocuments without modifying analyzers.

### Confirmed Invariants

- Analyzer Contract unchanged
- AnalysisDocument schema unchanged
- No new analyzers added
- No existing analyzers modified
- Evaluation harness operates on serialized JSON, not internal objects
- Benchmark corpora are data artifacts, not code

## Specification Validation

### Requirements Validated

- **M6-001**: Evaluation measures agreement, consistency, usefulness,
  explainability -- not correctness. Verified across all artifacts.
- **Knowledge boundary**: A4/A5-001, A6-001, A7-001, A15-001, A16-001
  all preserved. No evaluation artifact introduces external knowledge
  or truth claims.
- **Determinism**: Evaluation harness produces identical output for
  identical input (verified in tests).

## Known Limitations

- Golden datasets are schemas and guidelines only; no annotated data collected
- Benchmark corpora have minimal sample items
- Quantitative agreement metrics (F1, kappa) not yet computable
- Single implementation exists; cross-implementation comparison not possible
- No interface evaluation (browser extension, CLI, web app not yet built)

## Lessons Learned

1. **Evaluation infrastructure must be implementation-agnostic**: The harness
   operates on JSON AnalysisDocuments, not Python objects. This was a critical
   design choice that prevents the harness from depending on internal
   implementation details.

2. **Benchmark corpora and golden datasets serve different purposes**: Corpora
   measure behavior; datasets measure agreement. Conflating them would blur
   the boundary between measurement and truth claims.

3. **Immutability must be enforced by policy, not just code**: BENCH-TEMPORAL's
   immutability is documented in README with explicit change approval processes.
